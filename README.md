# Kvarta — сайт кофейной обжарки

**Демо:** https://kvarta-jpco.onrender.com  
**Технологии:** Java 17, Spring Boot, Thymeleaf, HTML, CSS, JavaScript, Spring Data JPA, H2, Maven, Docker.

## О проекте

Kvarta — сайт кофейной обжарки, который знакомит посетителей с ассортиментом кофе, ценами, подпиской и условиями доставки. Пользователь может оставить заявку на подписку, разовый заказ или задать вопрос через форму обратной связи.

## Основные возможности

- Страница с информацией о компании и особенностях свежей обжарки.
- Каталог кофе с ценами.
- Информация о подписке, доставке и самовывозе.
- Контакты и форма обратной связи.
- Серверная обработка заявок и сохранение в базе данных H2.
- Валидация номера телефона и защита от повторных заявок.
- Публичное развёртывание приложения на Render с помощью Docker.

## Технологии и решения

**Java 17 и Spring Boot** используются для серверной логики и обработки заявок.

**Thymeleaf, HTML, CSS и JavaScript** отвечают за отображение страниц и взаимодействие с пользователем.

**Spring Data JPA и H2** используются для хранения заявок. Выбрана файловая база H2, чтобы упростить настройку и запуск проекта без отдельного сервера базы данных.

**Docker и Render** используются для сборки и публикации приложения в интернете.

## Запуск локально

Требования: Java 17 и Maven (или Maven Wrapper, включённый в репозиторий).

1. Склонировать репозиторий:

   ```bash
   git clone https://github.com/ilya-JAVA/kvarta.git
   cd kvarta
   ```

2. Запустить приложение:

   На macOS/Linux:

   ```bash
   ./mvnw spring-boot:run
   ```

   На Windows:

   ```bat
   mvnw.cmd spring-boot:run
   ```

3. Открыть адрес `http://localhost:8088`.

   Если порт изменён в настройках приложения, использовать указанный там порт.

## Работа над проектом

Проект разрабатывался с использованием ИИ как вспомогательного инструмента для подготовки кода, поиска ошибок и решения технических вопросов. Самостоятельно выполнялись настройка проекта в IntelliJ IDEA, работа с Git и GitHub, проверка приложения и развёртывание на Render.

При тестировании пришлось корректировать длину поля номера телефона, чтобы оно принимало номера в формате `+375...`. Это показало необходимость проверять сгенерированный код на реальных сценариях, а не полагаться только на первоначальный вариант.

## Известные ограничения и дальнейшие улучшения

- Для надёжного хранения заявок в публичной среде необходимо использовать постоянное хранилище. Файловая база H2 на бесплатном Render может потерять данные при перезапуске или повторном развёртывании.
- Следующие шаги: проверить мобильную производительность с помощью Lighthouse, подготовить отчёт и при необходимости перенести данные в PostgreSQL.
- Дополнительное развитие проекта: интеграция уведомлений о новых заявках в Telegram.
